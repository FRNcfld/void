XMod 物品转化方块技术文档
1. 项目概述
XMod 是一个基于 Minecraft 1.20.1 Forge 的模组，添加了一个名为 X Block 的特殊方块。该方块提供了一个 GUI 界面，允许玩家将左侧格子中的全部物品一次性转化为当前选中标签（Tag）下的任意一种目标物品（数量不变），并标记为“已转化”。
转化后，玩家必须将左槽中的物品取出（任意方式，包括 shift+点击、手动移动、漏斗等），才能重置转化状态，允许再次放入新物品并进行新的转化。

本模组实现了：

自定义方块、方块实体、容器菜单和 GUI 屏幕。

基于物品标签的动态识别与选择（支持循环切换和下拉菜单）。

基于网络包的数据同步（服务端↔客户端）。

支持多语言本地化，所有提示文字可配置。

2.2 组件职责
组件	职责
XBlock	定义方块的属性（硬度、是否可交互），拦截右键事件打开 GUI，并负责破坏时掉落容器物品。
XBlockEntity	存储左槽物品、当前选中的标签索引、所有可用标签列表、转化状态（converted）。负责响应槽位变化、执行转化逻辑、发送数据同步包。
XMenu	定义槽位布局（左槽 + 玩家背包 + 快捷栏），作为服务端与客户端之间的数据容器，存储从服务端同步来的 GUI 数据（标签、物品列表、转化状态）。
XScreen	渲染 GUI 背景、标签显示、物品列表、翻页按钮、下拉菜单、转化状态提示。处理鼠标点击事件（切换标签、选择标签、翻页、点击物品转化）。
网络包	实现服务端↔客户端的数据传输，确保 GUI 状态实时同步。
3. 关键类详解
3.1 XBlockEntity （核心业务逻辑）
主要属性：

SimpleContainer container：只含一个槽位的容器（左槽）。

int selectedTagIndex：当前选中标签在 allTags 列表中的索引（-1 表示无标签）。

List<String> allTags：左槽物品所拥有的所有标签的字符串列表（完整 ResourceLocation）。

boolean converted：标记左槽物品是否已经转化完成。

关键方法：

onLeftSlotChanged()：当左槽物品发生变化时调用，更新 allTags 和 selectedTagIndex，并触发 sendGuiData()。

switchTag() / selectTag(int index)：循环切换或直接选择标签，并发送更新包。

convertAllAndGiveItem(Player player, int itemIndex)：

检查 converted，若为 true 则拒绝转化。

获取当前选中的标签，根据 itemIndex 取出目标物品。

将左槽物品全部转换为目标物品（数量不变）。

设置 converted = true，调用 sendGuiDataWithConverted(true) 同步状态。

getContainer()：返回 container 供 XMenu 使用。

saveAdditional / load：持久化存储 container、selectedTagIndex 和 converted。

重要细节：

container 重写了 setChanged()：每当容器内容变化（包括外部如漏斗取走物品），若 converted 为 true 则重置为 false，然后调用 onLeftSlotChanged()。这保证了任何方式取出物品后都会重置转化状态。

sendGuiData() 会附带 converted 状态一并发送。

3.2 XMenu （容器）
槽位：

左槽：索引 0，对应 XBlockEntity.container 的槽 0。

玩家背包：索引 1~36（3行 + 9个快捷栏）。

数据同步：

提供 updateGuiData(...) 方法，供网络包回调更新本地缓存数据（标签列表、选中索引、物品列表、转化状态）。

quickMoveStack 仅允许将左槽物品移入玩家背包（shift+点击）。

3.3 XScreen （客户端 GUI）
渲染元素：

背景纹理（x_gui.png，176×166）。

标签显示区（左上角，显示当前标签名 + 下三角符号）。

物品列表（右侧，3列，每页最多9个物品，带翻页按钮 < 和 >）。

转化状态提示（左槽下方）：

若未转化，显示绿色 "xmod.converter.ready"（可转化）。

若已转化，显示黄色 "xmod.converter.done"（转化已完成，请取出重置）。

下拉菜单（右键点击标签区域打开，左键选择）。

交互事件：

左键点击标签区域：发送 SwitchTagPacket（循环切换）。

右键点击标签区域：切换下拉菜单的打开/关闭。

左键点击下拉菜单的某一项：发送 SelectTagPacket 选择该标签。

左键点击物品列表中的某个物品：

若 converted 为 true，显示短暂提示 "xmod.converter.already_done"，不执行转化。

否则，若左槽非空，发送 ConvertPacket 执行转化。

若左槽为空，显示 "xmod.converter.no_source"。

点击翻页按钮：切换当前页码（仅客户端翻页，不向服务端通信）。

短暂消息：点击无效操作时，会在界面底部显示 3 秒的提示文字（通过 messageTimer 控制）。

4. 数据流与交互流程
4.1 转化流程（用户点击目标物品）
客户端 XScreen.mouseClicked 检测到点击物品列表中的某个物品。

检查 menu.isConverted()，若 true 则拒绝并显示提示。

检查左槽是否为空，为空则拒绝。

构造 ConvertPacket（包含方块位置和物品索引），通过 NetworkHandler.CHANNEL.sendToServer() 发送。

服务端 ConvertPacket.handle 接收，调用 XBlockEntity.convertAllAndGiveItem。

服务端执行：

读取左槽物品，获取数量 count。

根据 selectedTagIndex 和 itemIndex 获取目标物品。

创建数量为 count 的目标物品堆，设置到左槽。

标记 converted = true。

调用 sendGuiDataWithConverted(true) 向所有客户端发送更新包（包含新的标签列表、物品列表、converted 状态）。

客户端接收 UpdateGuiDataPacket，更新 XMenu 中的数据，XScreen 重新渲染，显示“转化已完成”提示。

4.2 重置流程（任意方式取出左槽物品）
当物品被玩家 shift+点击、手动拖出、或被漏斗等外部容器取走时，XBlockEntity.container 的 setChanged() 方法被触发。

在 setChanged() 中检测 converted 是否为 true，若是则重置为 false。

随后调用 onLeftSlotChanged()，更新标签列表，并发送 UpdateGuiDataPacket（converted 为 false）。

客户端收到更新后，界面变为“可转化”状态。

4.3 标签切换与选择
循环切换：客户端发送 SwitchTagPacket，服务端调用 switchTag()，更新 selectedTagIndex 并广播新数据。

下拉选择：客户端发送 SelectTagPacket（携带目标索引），服务端调用 selectTag(index)，更新并广播。

5. 网络同步协议
所有网络包均通过 SimpleChannel 传输，协议版本为 "1"。

包名	方向	内容	作用
UpdateGuiDataPacket	服务端→客户端	BlockPos, List<String> tags, int selectedIndex, List<ResourceLocation> items, boolean converted	同步完整 GUI 数据
SwitchTagPacket	客户端→服务端	BlockPos	请求循环切换标签
SelectTagPacket	客户端→服务端	BlockPos, int index	请求选择指定标签
ConvertPacket	客户端→服务端	BlockPos, int itemIndex	请求执行转化
注：UpdateGuiDataPacket 在服务端数据变化时自动广播给所有玩家，确保多人游戏下所有打开该方块的玩家界面同步。

6. 配置与本地化
6.1 语言文件
位于 assets/xmod/lang/ 下，支持 en_us.json 及其他语言。
可用键值：

json
{
  "block.xmod.x_block": "X Block",
  "container.xmod.x_block": "X Converter",
  "xmod.converter.done": "Conversion Done - Take out to reset",
  "xmod.converter.ready": "Ready to convert",
  "xmod.converter.already_done": "Already converted! Please take out the item.",
  "xmod.converter.no_source": "No source item in left slot."
}
所有提示文字均通过语言键获取，便于自定义和本地化。

6.2 GUI 纹理
需提供 assets/xmod/textures/gui/x_gui.png，尺寸 176×166 像素。代码中硬编码了关键坐标：

左槽： (44, 36)

标签显示区域： (80, 10)

物品列表起点： (80, 30)（每格 18×18）

翻页按钮： < 在 (70, 60)，> 在 (130, 60)
建议在纹理上绘制相应边框和背景以辅助定位。

7. 扩展与自定义指南
7.1 修改页面大小
在 XScreen 中修改常量 ITEMS_PER_PAGE（默认 9），并相应调整绘制逻辑中的行/列布局。

7.2 修改转化数量规则
如需设定“每次转化消耗指定数量”或“消耗一定数量生成另一个数量”，可修改 XBlockEntity.convertAllAndGiveItem 中的计算逻辑：

java
int count = source.getCount(); // 原样转换
// 可改为：
int consume = 2; // 每次消耗2个
int produce = 1; // 生成1个
if (count >= consume) { ... }
7.3 添加转化冷却时间
可在 XBlockEntity 中添加 long lastConvertTime，在 convertAllAndGiveItem 中检查时间间隔。

7.4 添加转化音效或粒子
在服务端执行转化后调用 level.playSound() 或 level.addParticle()。

7.5 支持 JEI/REI 等合成表模组
需额外实现 IRecipe 或使用 Ingredient 类，但本模组不包含此类集成。

8. 注意事项与已知限制
8.1 性能考虑
遍历所有物品获取标签下的物品列表是在服务端每次标签更新时执行，若标签包含大量物品（如 #minecraft:logs），可能造成瞬时 CPU 负载。可通过缓存结果或异步处理优化，但本实现为简化未做缓存。

网络包广播所有打开该方块的玩家，若同时有多人打开同一方块，数据同步频繁，但通常影响可接受。

8.2 兼容性
模组仅依赖 Forge 1.20.1，未使用其他 API。

支持多人游戏，所有交互均通过服务端逻辑和网络包实现数据同步。

8.3 已知问题
如果左槽物品无任何标签，标签显示区显示 "No Tag"，此时无法切换标签，物品列表为空，转化无法进行。

下拉菜单在标签数量较多时可能超出屏幕，目前限制最大高度为 100 像素，超出部分未滚动。如需完整显示，可添加滚动条或调整布局。

转化后的物品会保留原来的 NBT 数据吗？目前仅保留物品 ID 和数量，丢弃所有 NBT。如需保留，可复制源物品的 NBT 到目标物品（但需注意兼容性）。

8.4 测试建议
测试各种物品的标签（如 forge:ingots/iron, minecraft:planks）。

测试漏斗、投掷器等外部容器与方块的交互，确保 setChanged 触发重置。

测试多人同时打开同一方块的界面，观察数据同步是否及时。

附录：注册与构建
所有注册均通过 DeferredRegister 完成，模组主类在 FMLClientSetupEvent 中注册 XScreen 与 XMenu 的关联。
构建时需确保资源文件路径正确，纹理和语言文件均放置在 resources 对应目录。
